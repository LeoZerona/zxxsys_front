# 原题库与清洗库系统设计方案

## 一、业务关系说明

- **原题库（OriginalQuestionBank）**：原始题目库，存储所有题目数据
- **清洗库（CleaningWarehouse）**：原题库的副本，用于检测和标记重复题目
- **关系**：一个原题库可以创建多个清洗库（用于不同的清洗策略或时间点）

## 二、数据模型设计

### 2.1 数据库表结构

#### 1. 原题库表（original_question_banks）

```sql
CREATE TABLE original_question_banks (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(255) NOT NULL COMMENT '题库名称',
  description TEXT COMMENT '题库描述',
  storage BIGINT DEFAULT 0 COMMENT '占用空间（字节）',
  question_count INT DEFAULT 0 COMMENT '题目总数',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  created_by BIGINT COMMENT '创建人ID',
  status TINYINT DEFAULT 1 COMMENT '状态：1-启用，0-禁用',
  INDEX idx_created_at (created_at),
  INDEX idx_status (status)
) COMMENT='原题库表';
```

#### 2. 题目表（questions）

```sql
CREATE TABLE questions (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  bank_id BIGINT NOT NULL COMMENT '所属原题库ID',
  original_question_id BIGINT COMMENT '原始题目ID（如果是清洗库题目，指向原题库题目ID）',
  content TEXT NOT NULL COMMENT '题目内容',
  subject VARCHAR(100) COMMENT '科目',
  question_type ENUM('single', 'multiple', 'fill', 'shortAnswer', 'judge', 'essay') NOT NULL,
  difficulty ENUM('easy', 'medium', 'hard') DEFAULT 'medium',
  score DECIMAL(5,2) DEFAULT 0 COMMENT '分值',
  options JSON COMMENT '选择题选项（JSON数组）',
  correct_answer TEXT COMMENT '正确答案',
  analysis TEXT COMMENT '题目解析',
  content_hash VARCHAR(64) COMMENT '内容哈希值（用于重复检测）',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_bank_id (bank_id),
  INDEX idx_content_hash (content_hash),
  INDEX idx_question_type (question_type),
  INDEX idx_original_question_id (original_question_id),
  FOREIGN KEY (bank_id) REFERENCES original_question_banks(id) ON DELETE CASCADE
) COMMENT='题目表';
```

#### 3. 清洗库表（cleaning_warehouses）

```sql
CREATE TABLE cleaning_warehouses (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  original_bank_id BIGINT NOT NULL COMMENT '关联的原题库ID',
  name VARCHAR(255) NOT NULL COMMENT '清洗库名称',
  description TEXT COMMENT '清洗库描述',
  status ENUM('pending', 'processing', 'completed', 'failed') DEFAULT 'pending' COMMENT '清洗状态',
  duplicate_count INT DEFAULT 0 COMMENT '检测到的重复题目数量',
  total_questions INT DEFAULT 0 COMMENT '总题目数',
  cleaning_strategy VARCHAR(50) DEFAULT 'content_hash' COMMENT '清洗策略：content_hash-内容哈希，similarity-相似度',
  similarity_threshold DECIMAL(3,2) DEFAULT 0.95 COMMENT '相似度阈值（0-1）',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  completed_at DATETIME COMMENT '清洗完成时间',
  created_by BIGINT COMMENT '创建人ID',
  INDEX idx_original_bank_id (original_bank_id),
  INDEX idx_status (status),
  FOREIGN KEY (original_bank_id) REFERENCES original_question_banks(id) ON DELETE CASCADE
) COMMENT='清洗库表';
```

#### 4. 重复题目关系表（duplicate_questions）

```sql
CREATE TABLE duplicate_questions (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  warehouse_id BIGINT NOT NULL COMMENT '清洗库ID',
  question_id BIGINT NOT NULL COMMENT '题目ID（清洗库中的题目）',
  duplicate_with_id BIGINT NOT NULL COMMENT '重复的题目ID（清洗库中的另一个题目）',
  similarity_score DECIMAL(5,4) DEFAULT 1.0 COMMENT '相似度分数（0-1）',
  duplicate_type ENUM('exact', 'similar') DEFAULT 'exact' COMMENT '重复类型：exact-完全相同，similar-相似',
  status ENUM('pending', 'merged', 'kept', 'deleted') DEFAULT 'pending' COMMENT '处理状态',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_warehouse_id (warehouse_id),
  INDEX idx_question_id (question_id),
  INDEX idx_duplicate_with_id (duplicate_with_id),
  INDEX idx_status (status),
  FOREIGN KEY (warehouse_id) REFERENCES cleaning_warehouses(id) ON DELETE CASCADE,
  FOREIGN KEY (question_id) REFERENCES questions(id) ON DELETE CASCADE,
  FOREIGN KEY (duplicate_with_id) REFERENCES questions(id) ON DELETE CASCADE,
  UNIQUE KEY uk_question_duplicate (question_id, duplicate_with_id)
) COMMENT='重复题目关系表';
```

#### 5. 清洗日志表（cleaning_logs）

```sql
CREATE TABLE cleaning_logs (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  warehouse_id BIGINT NOT NULL COMMENT '清洗库ID',
  action VARCHAR(50) NOT NULL COMMENT '操作类型',
  message TEXT COMMENT '日志消息',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_warehouse_id (warehouse_id),
  FOREIGN KEY (warehouse_id) REFERENCES cleaning_warehouses(id) ON DELETE CASCADE
```

## 四、业务流程设计

### 4.1 创建清洗库流程

```
1. 用户在原题库页面点击"创建清洗库"
2. 填写清洗库信息（名称、描述、清洗策略）
3. 后端创建清洗库记录（status: pending）
4. 异步任务开始：
   a. 复制原题库的所有题目到清洗库（设置 original_question_id）
   b. 为每个题目计算内容哈希值（content_hash）
   c. 更新清洗库状态为 processing
5. 开始重复检测：
   a. 按内容哈希分组，找出完全相同的题目
   b. 如果使用相似度检测，计算相似度分数
   c. 记录重复关系到 duplicate_questions 表
6. 更新清洗库状态为 completed，记录完成时间
```

### 4.2 重复检测算法

#### 方案1：内容哈希（快速，适合完全重复）

```typescript
// 1. 计算题目内容哈希
function calculateContentHash(question: Question): string {
  // 标准化内容（去除空格、换行等）
  const normalized = question.content
    .replace(/\s+/g, '')
    .toLowerCase()
    .trim();
  
  // 使用 SHA-256 或 MD5
  return sha256(normalized);
}

// 2. 按哈希值分组
const hashGroups = new Map<string, number[]>();
questions.forEach(q => {
  const hash = q.contentHash;
  if (!hashGroups.has(hash)) {
    hashGroups.set(hash, []);
  }
  hashGroups.get(hash)!.push(q.id);
});

// 3. 找出重复组（数量 > 1）
hashGroups.forEach((questionIds, hash) => {
  if (questionIds.length > 1) {
    // 记录重复关系
    for (let i = 0; i < questionIds.length; i++) {
      for (let j = i + 1; j < questionIds.length; j++) {
        createDuplicateRelation(questionIds[i], questionIds[j], 'exact', 1.0);
      }
    }
  }
});
```

#### 方案2：相似度检测（适合相似但不完全相同的题目）

```typescript
// 使用文本相似度算法（如余弦相似度、编辑距离等）
function calculateSimilarity(q1: Question, q2: Question): number {
  // 方法1：余弦相似度（基于词向量）
  const vector1 = textToVector(q1.content);
  const vector2 = textToVector(q2.content);
  return cosineSimilarity(vector1, vector2);
  
  // 方法2：编辑距离（Levenshtein Distance）
  // return 1 - (levenshteinDistance(q1.content, q2.content) / Math.max(q1.content.length, q2.content.length));
}

// 检测相似题目
function findSimilarQuestions(questions: Question[], threshold: number = 0.95) {
  const duplicates: Array<{q1: number, q2: number, score: number}> = [];
  
  for (let i = 0; i < questions.length; i++) {
    for (let j = i + 1; j < questions.length; j++) {
      const similarity = calculateSimilarity(questions[i], questions[j]);
      if (similarity >= threshold) {
        duplicates.push({
          q1: questions[i].id,
          q2: questions[j].id,
          score: similarity
        });
      }
    }
  }
  
  return duplicates;
}
```

### 4.3 处理重复题目流程

```
1. 用户在清洗库页面查看重复题目列表
2. 对于每个重复组，用户可以选择：
   - 合并：保留一个题目，删除其他（或标记为已合并）
   - 保留：保留所有题目（标记为已保留，不再提示重复）
   - 删除：删除重复的题目
3. 后端更新 duplicate_questions 表的 status 字段
4. 如果选择合并或删除，更新 questions 表的相应记录
```

## 六、性能优化建议

1. **异步处理**：清洗任务使用消息队列（如 RabbitMQ、Redis Queue）异步处理
2. **批量操作**：重复检测时使用批量插入，减少数据库操作
3. **索引优化**：在 content_hash、bank_id、warehouse_id 等字段上建立索引
4. **分页加载**：重复题目列表使用分页，避免一次性加载大量数据
5. **缓存策略**：清洗进度、统计信息等可以缓存，减少数据库查询

## 七、扩展功能建议

1. **清洗策略模板**：保存常用的清洗策略配置
2. **自动清洗规则**：设置规则，自动处理某些类型的重复
3. **清洗报告**：生成详细的清洗报告（PDF/Excel）
4. **清洗历史**：记录每次清洗的详细信息，支持对比
5. **智能推荐**：基于相似度推荐需要合并的题目

## 八、注意事项

1. **数据一致性**：创建清洗库时，确保原题库数据不被修改
2. **事务处理**：处理重复题目时使用事务，确保数据一致性
3. **错误处理**：清洗过程中出现错误，记录日志并更新状态
4. **权限控制**：区分原题库和清洗库的操作权限
5. **数据备份**：清洗操作前建议备份数据
